# ขอบเขต MVP — ระบบสต็อกและบิลร้านขายส่งชุดชั้นใน

สรุปจากการสัมภาษณ์ผู้ใช้ วันที่ 14 ตุลาคม 2026 ดูหลักฐานและรายละเอียดการสนทนาใน [discovery.md](discovery.md) และคำศัพท์ใน [GLOSSARY.md](../../GLOSSARY.md)

เอกสารนี้สรุปขอบเขตธุรกิจที่ตกลงแล้ว รายละเอียดที่ยังไม่ได้เลือกอยู่ในหัวข้อท้ายเอกสาร กติกาล่าสุดคือขายแล้วตัดสต็อกทันที ไม่มีการปิดวัน

## ปัญหาและเป้าหมาย

ร้านมีบันทึกสต็อกบนกระดาษ แต่ยังต้องตรวจของจริงและใช้ข้อมูลในการขายหน้าร้านกับ LINE เป้าหมายของ MVP คือให้เจ้าของร้านดูจำนวนที่ยังขายได้ จองสินค้า ออกบิล และบันทึกการเคลื่อนไหวสินค้าในระบบเดียวบนมือถือ

ยังไม่มีข้อมูลยืนยันว่าระบบจะลดเวลา ลดสินค้าขาด หรือเพิ่มยอดขายได้เท่าไร ผลเหล่านี้ต้องตรวจจากการทดลองใช้งานจริง

## ผู้ใช้และข้อกำหนด

- เจ้าของร้านขายส่งชุดชั้นใน อายุ 40 ปีขึ้นไป ที่ไม่คุ้นเทคโนโลยี เป็นผู้ใช้งานและบันทึกข้อมูลหลักเพียงคนเดียว
- ใช้มือถือเป็นหลัก และมีอินเทอร์เน็ตพร้อมใช้งาน
- ข้อมูลเก็บออนไลน์ เข้าสู่ระบบจากมือถือเครื่องใหม่แล้วใช้ข้อมูลเดิมได้
- ฝั่งหน้าเว็บใช้ Vite + TypeScript + React + Tailwind
- วิธีเข้าสู่ระบบพักไว้ตามคำขอผู้ใช้ ยังไม่เลือกบริการฐานข้อมูล ระบบหลังบ้าน หรือวิธีสำรองข้อมูล

## ฟีเจอร์ที่ตกลงแล้ว

### 1. สินค้าและยอดคงเหลือ

- สินค้าหนึ่งรหัสมีรูปหลักและมีหลายไซซ์/สีได้
- ลำดับการเลือกและแสดงผล: รหัสสินค้า → ไซซ์ → สี พร้อมจำนวนคงเหลือและจำนวนที่ยังขายได้
- หน่วยนับต่างกันตามสินค้า เช่น แพ็กหรือมัด ต้องเก็บหน่วยของสินค้านั้น ไม่กำหนดอัตราแปลงเดียวกันทั้งร้าน
- ราคาขายคงที่ตามรหัส ไซซ์ และสี บางชุดมีราคาเท่ากันและบางชุดต่างกัน
- หนึ่งแพ็กมีไซซ์เดียว สีภายในจัดไว้แน่นอน อาจเป็นสีเดียวหรือคละหลายสี
- แพ็กคละสีแสดงเป็นตัวเลือก “คละสี” ในไซซ์นั้น พร้อมรายละเอียดสีภายใน นับสต็อกเป็นแพ็ก ไม่แยกจำนวนให้สีภายใน
- สินค้าที่นับเป็นแพ็กขาย คืน หรือเปลี่ยนทั้งแพ็กเท่านั้น

### 2. ยอดเริ่มต้น รับเข้า และปรับยอด

- นำข้อมูลจากกระดาษเดิมมากรอก แล้วตรวจนับของจริงเพื่อยืนยันยอดเริ่มต้น
- บันทึกสินค้าเข้าแล้วเพิ่มสต็อกทันที
- เจ้าของร้านปรับยอดให้ตรงกับของจริงได้
- ถ้าปรับแล้วของจริงน้อยกว่าจำนวนที่จองอยู่ ให้บันทึกยอดตามจริงและแจ้ง “ของไม่พอ” ไม่บังคับยกเลิกการจองก่อน
- การยกเลิกการจองยังเป็นการตัดสินใจของเจ้าของร้าน ระบบไม่ยกเลิกให้อัตโนมัติ

### 3. การจองจาก LINE

- เจ้าของร้านกรอกชื่อลูกค้า สินค้า ไซซ์ สี และจำนวนจากบทสนทนา LINE เอง
- จองได้ตั้งแต่ลูกค้าแสดงความสนใจ
- การจองลดจำนวนที่ยังขายได้ แต่ยังไม่ตัดสต็อกคงเหลือ
- การจองไม่มีวันหมดอายุ เจ้าของร้านยกเลิกเอง เมื่อยกเลิกจะปล่อยจำนวนที่กันไว้
- สร้างบิลจากรายการจองได้ โดยนำทุกรายการและจำนวนที่จองไปขายครบทั้งหมด
- ไม่รองรับการซื้อบางส่วนแล้วค้างจองส่วนที่เหลือ
- เมื่อขายจากการจอง ปลดจำนวนที่จองและตัดสต็อกครั้งเดียว ไม่หักซ้ำ

### 4. การขายและบิลเงินสด

- ทุกการขายสร้างบิลในระบบ หนึ่งบิลต่อการซื้อของลูกค้าหนึ่งราย
- บันทึกบิลเมื่อขายสำเร็จแล้วตัดสต็อกทันที ไม่มีการปิดวันหรือกรอกยอดขายรวมภายหลัง
- ห้ามจองหรือขายเกินจำนวนที่ยังขายได้
- Export บิลเป็นรูปเพื่อให้เจ้าของร้านนำไปส่งเอง การ Export ซ้ำไม่ทำให้ตัดสต็อกอีก
- ข้อมูลบนบิล: ชื่อร้าน เบอร์ติดต่อ เลขที่บิล วันที่ ชื่อลูกค้าแบบเว้นว่างได้ รหัสสินค้า ไซซ์ สี จำนวน หน่วย ราคาต่อหน่วย ยอดแต่ละรายการ และยอดรวม
- แก้บิลเดิมได้ ปรับสต็อกตามส่วนต่างของจำนวนและเก็บประวัติ การแก้เฉพาะราคาไม่เปลี่ยนจำนวนสินค้า
- ยกเลิกบิลที่กรอกผิดได้ คืนสต็อกและเก็บประวัติ หากลูกค้ารับของไปแล้วนำมาคืน ให้ใช้ขั้นตอนรับคืนสินค้า

### 5. คืนและเปลี่ยนสินค้า

- รองรับทั้งอ้างอิงบิลเดิมและไม่มีบิลเดิม
- กรณีมีบิลเดิม ระบบสามารถอ้างอิงรายการและจำนวนที่ซื้อได้ กรณีไม่มีบิล เจ้าของร้านกรอกรายการเอง และระบบไม่สามารถยืนยันยอดที่เคยซื้อจากบิลได้
- เลือกได้ว่า “คืนเข้าสต็อกพร้อมขาย” หรือ “รับคืนแต่ขายต่อไม่ได้”
- ของคืนที่พร้อมขายเพิ่มกลับเข้าสต็อกทันที ส่วนของที่ขายต่อไม่ได้ไม่เพิ่มยอดพร้อมขาย
- สินค้าใหม่ที่ส่งให้ลูกค้าในการเปลี่ยนตัดสต็อกทันทีตามกติกาการขายล่าสุด
- ไม่คำนวณเงินคืนหรือส่วนต่างราคา เจ้าของร้านจัดการเงินจริงเอง
- สินค้าแบบแพ็กต้องรับคืน/เปลี่ยนเป็นแพ็กเต็ม

## กติกาสต็อกหลัก

**จำนวนที่ยังขายได้ = สต็อกคงเหลือที่บันทึกไว้ − จำนวนที่จองอยู่**

สต็อกคงเหลือได้หักการขายสำเร็จแล้ว จึงไม่หักจำนวนจากบิลซ้ำในสูตรนี้

| เหตุการณ์ | สต็อกคงเหลือ | จำนวนที่จองอยู่ |
| --- | --- | --- |
| รับสินค้าเข้า | เพิ่มทันที | ไม่เปลี่ยน |
| จอง | ไม่เปลี่ยน | เพิ่ม |
| ยกเลิกการจอง | ไม่เปลี่ยน | ลด |
| ขายปกติ | ลดทันที | ไม่เปลี่ยน |
| ขายจากการจอง | ลดทันที | ลดตามจำนวนที่เปลี่ยนเป็นการขาย |
| Export รูปบิล | ไม่เปลี่ยน | ไม่เปลี่ยน |
| แก้จำนวนในบิล | ปรับตามส่วนต่าง | ต้องคงความถูกต้องของรายการจองที่เกี่ยวข้อง |
| แก้เฉพาะราคา | ไม่เปลี่ยน | ไม่เปลี่ยน |
| ยกเลิกบิลที่กรอกผิด | คืนจำนวนที่เคยตัด | กติกากรณีบิลมาจากการจองยังต้องกำหนด |
| รับคืนพร้อมขาย | เพิ่มทันที | ไม่เปลี่ยน |
| รับคืนขายต่อไม่ได้ | ไม่เพิ่ม | ไม่เปลี่ยน |
| จ่ายสินค้าใหม่ในการเปลี่ยน | ลดทันที | ไม่เปลี่ยนถ้าไม่มีการจองเกี่ยวข้อง |
| ปรับยอดจากตรวจนับ | เปลี่ยนเป็นยอดของจริง | ไม่ยกเลิกการจองอัตโนมัติ |

หากสต็อกจริงต่ำกว่าจำนวนที่จอง ให้แสดงของไม่พอ และยังห้ามการขาย/จองเพิ่มเกินจำนวนที่มี การแสดงผลกรณีขาดของต้องออกแบบให้เห็นความขาดแคลนชัดเจน

## สิ่งที่ไม่อยู่ใน MVP

- ขั้นตอนปิดวันหรือกรอกยอดขายรวมรายวันด้วยมือ
- การขายโดยไม่สร้างบิล
- ตำแหน่งเก็บสินค้า ชั้น หรือชั้นวาง
- การอ่านบทสนทนา LINE หรือส่งบิล LINE อัตโนมัติ
- การจองหมดอายุอัตโนมัติ
- การซื้อบางส่วนจากการจองแล้วคงส่วนที่เหลือไว้
- การแยกขาย/คืนบางตัวจากแพ็ก
- การคำนวณเงินคืนหรือส่วนต่างราคาเมื่อเปลี่ยนสินค้า

## แนวทางหน้าจอที่เสนอ — ยังไม่ใช่ข้อสรุปการออกแบบ

1. สินค้าและสต็อก: ค้นหารหัส ดูรูป เลือกไซซ์ แล้วดูสี/คละสีและจำนวน
2. สร้างบิล: เลือกสินค้า จำนวน ตรวจยอด บันทึกการขาย และ Export รูป
3. รายการจอง: ดูรายการค้าง สร้างจอง ยกเลิก และสร้างบิลจากการจอง
4. ประวัติบิล: เปิดบิล Export ซ้ำ แก้ข้อมูล และยกเลิกบิลที่ผิด
5. จัดการสต็อก: ยอดเริ่มต้น รับเข้า และปรับยอด
6. คืน/เปลี่ยน: เลือกบิลเดิมหรือกรอกเอง ตรวจสภาพของคืน และเลือกสินค้าใหม่

การจัดเมนูและการรวมหน้าจอควรทดลองกับเจ้าของร้านบนมือถือก่อนเลือกแบบสุดท้าย

## เกณฑ์ตรวจรับหลักที่เสนอจากกติกาที่ตกลง

ตัวเลขด้านล่างเป็นข้อมูลจำลองสำหรับตรวจระบบ ไม่ใช่ข้อมูลสต็อกของร้าน

- มี 10 แพ็ก ขายผ่านบิล 3 แพ็ก ต้องเหลือ 7 ทันที Export ซ้ำยังเหลือ 7
- มี 10 แพ็ก จอง 3 แพ็ก ต้องแสดงขายได้ 7 เมื่อขายครบจากจอง สต็อกเหลือ 7 ยอดจองนั้นสิ้นสุด และขายได้ยังเป็น 7
- จอง 3 แพ็กแล้วต้องไม่สร้างบิลจากจองเพียง 2 แพ็กโดยค้างจองอีก 1
- จำนวนที่ยังขายได้ 2 แพ็ก ต้องไม่บันทึกจองหรือขาย 3 แพ็ก
- ขาย 3 แพ็กแล้วแก้บิลเป็น 2 ต้องคืนสต็อก 1 และมีประวัติ แก้ราคาอย่างเดียวไม่เปลี่ยนสต็อก
- ยกเลิกบิลที่ผิดต้องคืนสต็อกครั้งเดียว
- รับคืนพร้อมขาย 1 แพ็ก ต้องเพิ่ม 1 ทันที รับคืนขายต่อไม่ได้ต้องไม่เพิ่มยอดพร้อมขาย
- เปลี่ยนของคืนพร้อมขาย 1 แพ็กเป็นสินค้าใหม่ 1 แพ็ก ต้องเพิ่มรายการเดิมและลดรายการใหม่ทันที
- มีจอง 5 แพ็กแต่ตรวจนับจริงเหลือ 3 ต้องบันทึก 3 ได้และแจ้งของไม่พอ โดยไม่ยกเลิกจองเอง
- แพ็กคละสีต้องถูกนับเป็นแพ็กเดียวและมีไซซ์เดียว ไม่เพิ่มยอดคงเหลือซ้ำตามจำนวนสีภายใน
- เข้าสู่ระบบจากเครื่องใหม่ต้องพบข้อมูลเดิม เมื่อเลือกและเชื่อมระบบออนไลน์แล้ว

## รายละเอียดที่ยังเปิดไว้

### พักไว้ตามคำขอผู้ใช้

- วิธีเข้าสู่ระบบ: ยังไม่เลือกอีเมล/รหัสผ่านหรือเบอร์มือถือ/OTP

### ต้องกำหนดก่อนพัฒนาส่วนที่เกี่ยวข้อง

- บริการฐานข้อมูล ระบบหลังบ้าน การจัดเก็บรูป และนโยบายสำรอง/กู้ข้อมูล
- รายการสินค้าจริง หน่วยนับ รายละเอียดแพ็ก สี ไซซ์ และราคา ข้อมูลจากภาพไม่ใช่ชุดข้อมูลพร้อมนำเข้า
- รูปแบบไฟล์และเลย์เอาต์รูปบิล วิธีเพิ่ม/เปลี่ยนรูปสินค้า
- กติกาแก้หรือยกเลิกบิลที่มีรายการคืน/เปลี่ยนเชื่อมอยู่ เพื่อไม่คืนสต็อกซ้ำหรือคืนเกินจำนวนเดิม
- การยกเลิกบิลที่สร้างจากจองจะนำการจองเดิมกลับมาหรือปิดไว้
- ประวัติการปรับยอดสต็อก: ยังไม่ตกลงว่าต้องมีหรือไม่ “ไม่เป็นไร” ถูกตีความว่าไม่บังคับเหตุผล ไม่ใช่การยืนยันตัดประวัติทั้งหมด
- กติกาสินค้าหน่วยอื่นนอกจากแพ็กที่ยังไม่ได้ยกตัวอย่าง
- วิธีวัดผลนำร่อง เช่น เจ้าของร้านทำงานหลักบนมือถือได้ด้วยตัวเอง และจำนวนตรงกับตรวจนับจริง โดยยังไม่กำหนดตัวเลขผลลัพธ์ทางธุรกิจ

รายการที่ยังเปิดไม่ใช่ฟีเจอร์ที่ตกลงให้เพิ่มโดยอัตโนมัติ ต้องแยกจากข้อกำหนดที่ยืนยันแล้วเมื่อทำสเปกและแผนพัฒนา
