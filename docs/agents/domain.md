# Domain Docs

This project uses one domain context.

- Before exploring domain code, read the root `GLOSSARY.md` and relevant decisions in `docs/adr/`.
- If these documents do not exist, continue. Create them lazily as terms and decisions are resolved.
- Use glossary vocabulary in specs, task titles, code discussions, and tests.
- Keep the glossary limited to domain definitions. Record discovery notes and implementation details separately.
- Create an ADR only for a decision that is costly to reverse, surprising without context, and based on a real trade-off.
- Surface conflicts with existing ADRs before proposing a conflicting change.
