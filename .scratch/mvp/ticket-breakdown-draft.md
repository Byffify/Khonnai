# ร่างการแบ่งงาน MVP

**Status:** approved-and-published

อ้างอิง [spec.md](spec.md) ผู้ใช้ยืนยันการแบ่งงานว่า “พอดี” วันที่ 14 ตุลาคม 2026 เผยแพร่แล้วเป็นหนึ่งไฟล์ต่อหนึ่งงาน ดูรายการปัจจุบันที่ [index.md](index.md) และใช้ไฟล์งานแยกเป็นแหล่งสถานะงาน

ทุกงานพัฒนารวมหน้าจอ ข้อมูลที่บันทึก กติกาธุรกิจ และการตรวจพฤติกรรมที่เกี่ยวข้อง งาน 01 เป็นการตัดสินใจก่อนพัฒนา ไม่ใช่งานเพิ่มฟีเจอร์

## 01 — สรุประบบออนไลน์และกติกาข้อมูลที่ยังเปิด

**Blocked by:** None

**What it delivers:** ข้อตกลงที่ใช้พัฒนาระบบออนไลน์จริง โดยไม่เลือกวิธีล็อกอินที่ผู้ใช้พักไว้เอง

- [ ] เลือกวิธีล็อกอิน บริการข้อมูลและรูป พร้อมข้อจำกัดและการสำรอง/กู้ข้อมูล
- [ ] กำหนดการแก้/ยกเลิกบิลที่มีคืน/เปลี่ยนเชื่อม และการยกเลิกบิลจากจอง
- [ ] สรุปประวัติปรับยอด วิธีจัดการรูป และรูปแบบไฟล์บิล
- [ ] กำหนดการนับหน่วยอื่นนอกจากแพ็กจากตัวอย่างจริง หากนำเข้ามาใช้
- [ ] บันทึกข้อสรุปโดยแยกสิ่งที่ผู้ใช้เลือกจากแนวทางเทคนิค

**Note:** งานนี้ยังต้องการคำตอบผู้ใช้ โดยเฉพาะล็อกอินที่พักไว้ ไม่ใช่งานที่ AI เลือกทุกข้อเองได้

## 02 — เปิดข้อมูลร้านออนไลน์และสร้างสินค้าพร้อมยอดเริ่มต้น

**Blocked by:** 01 — สรุประบบออนไลน์และกติกาข้อมูลที่ยังเปิด

**What it delivers:** เจ้าของร้านเข้าระบบ เพิ่มสินค้า/รูป/ไซซ์/สี/คละสี หน่วย ราคา และยอดเริ่มต้นจากมือถือ เปิดใหม่แล้วข้อมูลยังอยู่

- [ ] ใช้ Vite + TypeScript + React + Tailwind และการเข้าสู่ระบบตามข้อสรุป
- [ ] เพิ่มและแก้ข้อมูลสินค้า รูปหลัก ตัวเลือกไซซ์/สี/คละสี หน่วย และราคา
- [ ] เริ่มจากข้อมูลจริงหรือสถานะว่าง ไม่มีสินค้าจำลองในระบบร้าน
- [ ] กรอกยอดเริ่มต้นจากกระดาษแล้วตรวจนับจริงได้
- [ ] แพ็กคละมีไซซ์เดียวและยอดเดียว ไม่แยกสต็อกสีภายใน
- [ ] เปิดข้อมูลจากอีก session ได้ และป้องกันการเข้าถึงข้อมูลร้านโดยไม่ได้เข้าสู่ระบบ
- [ ] ตรวจการใช้งานและการกรอกบนมือถือจริงผ่าน browser

## 03 — รับสินค้าเข้าและปรับยอดตามการตรวจนับ

**Blocked by:** 02 — เปิดข้อมูลร้านออนไลน์และสร้างสินค้าพร้อมยอดเริ่มต้น

**What it delivers:** เจ้าของร้านเลือกสินค้า รับเข้าเพิ่มทันที หรือแก้ยอดตามของจริง แล้วเปิดใหม่พบยอดที่บันทึก

- [ ] รับเข้าตามหน่วยสินค้าพร้อมเพิ่มสต็อกทันที
- [ ] ปรับยอดจริงได้โดยไม่บังคับเหตุผล ใช้กติกาประวัติตามงาน 01
- [ ] สต็อกจริงไม่เป็นจำนวนติดลบ และแพ็กใช้จำนวนแพ็กเต็ม
- [ ] บันทึกซ้ำจากคำขอเดิมไม่เพิ่มยอดซ้ำ
- [ ] บันทึกล้มเหลวไม่แสดงสำเร็จ และข้อมูลที่กรอกยังแก้/ลองใหม่ได้
- [ ] ตรวจการคงอยู่ของยอดออนไลน์และความถูกต้องจากหน้าใช้งาน

## 04 — ขายผ่านบิลเงินสดและตัดสต็อกทันที

**Blocked by:** 02 — เปิดข้อมูลร้านออนไลน์และสร้างสินค้าพร้อมยอดเริ่มต้น

**What it delivers:** เลือกรหัส → ไซซ์ → สี/คละสี กรอกจำนวน ดูราคากับยอดรวม และบันทึกบิลพร้อมตัดสต็อก

- [ ] ข้อมูลบนบิลครบตามสเปก ชื่อลูกค้าเว้นได้
- [ ] ทุกการขายสร้างบิล ไม่มีการกรอกยอดรวมสิ้นวัน
- [ ] ขายสำเร็จตัดทันที บิลและสต็อกสำเร็จร่วมกัน
- [ ] ห้ามเกินจำนวนที่ยังขายได้ และจำนวนแพ็กต้องเต็ม
- [ ] ราคาบนบิลเก่ายังเดิมเมื่อแก้ราคาสินค้า
- [ ] กด/ส่งคำขอซ้ำไม่สร้างบิลหรือหักยอดซ้ำ
- [ ] เปิดประวัติบิลและข้อมูลหลังขายได้บนมือถือ

## 05 — Export บิลเงินสดเป็นรูป

**Blocked by:** 04 — ขายผ่านบิลเงินสดและตัดสต็อกทันที

**What it delivers:** เปิดบิลที่บันทึกแล้ว Export รูปอ่านได้เพื่อส่งลูกค้าเอง

- [ ] รูปแบบไฟล์ตามข้อสรุปงาน 01 พร้อมข้อมูลบิลและยอดตรง
- [ ] ภาษาไทย รายการหลายบรรทัด และบิลยาวไม่มีข้อความหาย
- [ ] Export ซ้ำไม่เปลี่ยนสต็อกหรือสร้างบิลเพิ่ม
- [ ] ทดลองเปิด/บันทึกรูปบนมือถือ และแจ้งเมื่อ Export ไม่สำเร็จ

## 06 — แก้บิลและยกเลิกบิลผิดพร้อมประวัติ

**Blocked by:** 04 — ขายผ่านบิลเงินสดและตัดสต็อกทันที

**What it delivers:** เจ้าของร้านเปิดบิล แก้รายการ/ราคา หรือยกเลิกบิลผิด แล้วเห็นสต็อกและประวัติถูกต้อง

- [ ] แก้จำนวนปรับตามส่วนต่าง การแก้ราคาไม่เปลี่ยนจำนวน
- [ ] ตรวจจำนวนที่เพิ่มก่อนบันทึก และไม่ทับข้อมูลจากฉบับเก่า
- [ ] ยกเลิกคืนสต็อกครั้งเดียว มีประวัติและสถานะบิลชัดเจน
- [ ] ใช้กติกาบิลจากจองและบิลที่มีคืน/เปลี่ยนตามข้อสรุปงาน 01
- [ ] ไม่ทำให้ของคืนและการแก้บิลคืนสต็อกซ้ำ

## 07 — จองสินค้าและยกเลิกจองจากมือถือ

**Blocked by:** 04 — ขายผ่านบิลเงินสดและตัดสต็อกทันที

**What it delivers:** เจ้าของร้านกรอกจองจาก LINE แล้วจำนวนที่ยังขายได้ลดลง เปิดรายการค้างหรือยกเลิกจองได้

- [ ] มีชื่อลูกค้า รายการ/ไซซ์/สี และจำนวน
- [ ] จองไม่ตัดสต็อก แต่กันจำนวนที่ยังขายได้
- [ ] ห้ามเกินจำนวนที่มี ใช้การตรวจจากข้อมูลออนไลน์ล่าสุด
- [ ] ไม่มีหมดอายุอัตโนมัติ ยกเลิกเองและคืนจำนวนพร้อมขายครั้งเดียว
- [ ] เส้นทางขายปกติต้องเคารพยอดจองด้วย ไม่ใช่เฉพาะหน้าจอง
- [ ] กดซ้ำไม่สร้างจองซ้ำหรือปล่อยยอดซ้ำ

## 08 — ขายครบจากจองและเตือนเมื่อของจริงไม่พอ

**Blocked by:** 03 — รับสินค้าเข้าและปรับยอดตามการตรวจนับ; 07 — จองสินค้าและยกเลิกจองจากมือถือ

**What it delivers:** สร้างบิลจากจองครบทั้งหมดโดยไม่หักยอดซ้ำ และแจ้งของไม่พอเมื่อปรับยอดจริงต่ำกว่ายอดจอง

- [ ] ใช้รายการและจำนวนจากจองครบ ไม่ซื้อบางส่วนแล้วค้างจอง
- [ ] ปลดจองและตัดสต็อกพร้อมกันครั้งเดียว
- [ ] สต็อก 10 จอง 3 แปลงเป็นบิลแล้วเหลือ 7 และขายได้ 7
- [ ] ถ้าของไม่พอ ห้ามขายจากจองและคงรายการจองจนเจ้าของจัดการ
- [ ] ปรับของจริงเป็น 3 เมื่อจอง 5 ได้ แจ้งขาด 2 ไม่บังคับยกเลิกก่อน
- [ ] ยกเลิก/แก้บิลจากจองตามข้อสรุปงาน 01 และไม่สร้างยอดกันซ้ำ

## 09 — รับคืนทั้งมีและไม่มีบิลเดิม

**Blocked by:** 06 — แก้บิลและยกเลิกบิลผิดพร้อมประวัติ

**What it delivers:** เลือกบิลหรือกรอกของคืนเอง เลือกพร้อมขาย/ขายต่อไม่ได้ แล้วเก็บรายการพร้อมยอดสต็อกถูกต้อง

- [ ] ของพร้อมขายเพิ่มทันที ของขายต่อไม่ได้ไม่เพิ่มยอดพร้อมขาย
- [ ] แบบแพ็กรับคืนเต็มแพ็ก
- [ ] ถ้ามีบิล ตรวจยอดคืนสะสมไม่เกินที่ขายตามกติกาบิลล่าสุด
- [ ] ไม่มีบิลให้เจ้าของกรอกเอง ไม่แสดงว่าได้ตรวจยอดซื้อเดิมแล้ว
- [ ] รับคืนซ้ำจากคำขอเดียวไม่เพิ่มสต็อกซ้ำ
- [ ] แก้/ยกเลิกบิลที่ผูกคืนไม่ทำสต็อกซ้ำตามกติกางาน 01
- [ ] ไม่คำนวณเงินคืน

## 10 — เปลี่ยนสินค้าและบันทึกบิลสินค้าใหม่

**Blocked by:** 09 — รับคืนทั้งมีและไม่มีบิลเดิม

**What it delivers:** รับของเดิม เลือกสินค้าใหม่ สร้างบิลของใหม่ตามกติกาทุกการขายมีบิล แล้วเพิ่ม/ลดสต็อกทันที

- [ ] รองรับอ้างบิลเดิมและไม่มีบิลเดิมเช่นเดียวกับรับคืน
- [ ] คืนของเดิมเพิ่มเฉพาะพร้อมขาย สินค้าใหม่ตัดทันทีและมีบิล
- [ ] ตรวจสินค้าใหม่ไม่เกินจำนวนที่ยังขายได้ รวมยอดจองที่ใช้งานอยู่
- [ ] การบันทึกส่วนรับคืนและขายของใหม่ต้องไม่ค้างครึ่งรายการเมื่อส่วนหนึ่งล้มเหลว
- [ ] บิลและการคืนเชื่อมกับรายการเปลี่ยนโดยไม่บันทึกการเคลื่อนไหวซ้ำ
- [ ] สินค้าแบบแพ็กใช้เต็มแพ็ก ไม่คำนวณเงินคืน/ส่วนต่าง
- [ ] ตรวจเส้นทางเปลี่ยนและกติกาแก้/ยกเลิกที่ผูกกับรายการนี้

## แนวทางทำงานร่วมกัน

- ทุกงานพัฒนาทดสอบผลลัพธ์ผ่านบริการธุรกิจ/ข้อมูลออนไลน์ และตรวจหน้าจอที่เพิ่มบนมือถือ
- ไม่แยกเป็นงาน “ทำฐานข้อมูลทั้งหมด” แล้ว “ทำ API ทั้งหมด” แล้ว “ทำหน้าจอทั้งหมด” เพราะจะยังทดลองใช้ไม่ได้เมื่อจบแต่ละงาน
- งาน 02 ส่งมอบสินค้าและยอดเริ่มต้นที่ใช้งานได้ งาน 03 และ 04 ต่างใช้ยอดจากงาน 02 ได้ จึงไม่บังคับให้การขายรอหน้ารับเข้า
- งาน 07 รอเส้นทางขายเพื่อทดสอบว่าการขายเคารพยอดจอง งาน 08 รอการปรับยอดและจองซึ่งมีเส้นทางขายแล้ว งาน 09 รอการแก้บิลเพื่อให้ทดสอบบิลที่มีคืนเชื่อมได้ งาน 10 รอรับคืนและมีเส้นทางขายจากงานก่อนหน้า
- งาน Export ไม่เป็นเงื่อนไขของการคำนวณสต็อก แต่ต้องเสร็จเป็นส่วนหนึ่งของ MVP ทั้งหมด
- รูปแบบนี้เป็นลำดับพึ่งพา ไม่ได้อนุมัติให้เริ่มหลาย agent หรือหลายงานพร้อมกัน
