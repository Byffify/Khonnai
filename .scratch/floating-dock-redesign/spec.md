# Khonnai: Floating Dock และพื้นที่ทำงานทั้ง 5 หน้า

วันที่: 19 ตุลาคม 2026

## ข้อตกลงและขอบเขตของแบบ

ผู้ใช้เลือกภาพ C — Floating Dock ให้เป็นทิศทาง navigation บน desktop และ mobile และขอออกแบบพื้นที่ Inventory เพิ่ม พร้อมใช้ธีมเดียวกันในสินค้า บิล จอง คืน/เปลี่ยน และตั้งค่า

ผู้ใช้อนุมัติให้สรุปและเริ่มพัฒนาเมื่อ 19 ตุลาคม 2026 ข้อสรุปล่าสุดคือ Quiet Gallery แบบสมดุล เพราะเจ้าของร้านน่าจะจำรหัสและรูปประกอบกัน โดยใช้ C Floating Dock ในทั้ง 5 หน้า งานพัฒนารอบนี้ทำ inline ตาม plan.md

ผู้ใช้หลักเป็นเจ้าของร้านขายส่ง อายุ 40 ปีขึ้นไป งานสำคัญคือค้นหารหัส เลือกไซซ์ ดูสีและจำนวนที่ยังขายได้ แล้วบันทึกงานร้านโดยไม่กรอกซ้ำ

## โครงหน้าร่วม

ทุกหน้ามี header ขนาดเล็ก: Brand เดิมด้านซ้าย และบริบทข้อมูลร้านตามโหมดจริงด้านขวา บริเวณเนื้อหาเป็นพื้นขาวและอยู่กึ่งกลางจอ

Floating Dock เป็นเจ้าของ navigation ชุดเดียวใน `App` ทุกขนาดจอ ใช้รายการ สินค้า / บิล / จอง / คืน/เปลี่ยน / ตั้งค่า พร้อม icon และชื่อเสมอ รายการที่เลือกใช้พื้นน้ำเงินอ่อนและ `aria-current=page` การเปลี่ยนหน้ายังผ่าน guard เดิม

Desktop ใช้ dock กว้างไม่เกิน 620px ลอยกึ่งกลางด้านล่าง ห่างขอบ 16px Mobile ใช้ความกว้างไม่เกินหน้าจอลบ 16px พร้อม safe area ของอุปกรณ์ แต่ละหน้ามีพื้นที่ท้ายเพียงพอให้รายการสุดท้าย ข้อผิดพลาด และปุ่มบันทึกเลื่อนพ้น dock ได้

ตัวเลขเป็น tabular figures การ hover ไม่ใช่วิธีเดียวที่ทำให้พบปุ่ม สถานะ focus ต้องมองเห็นได้บนพื้นกระจกและพื้นขาว

## สินค้า: รูปและรหัสประกอบกัน

ส่วนหัวมีชื่อหน้าและปุ่มเพิ่มสินค้า ตามด้วยช่องค้นหาที่มี label คงที่ แถวสรุปใช้จำนวนรหัสที่แสดง ไม่บวกรวมจำนวนสินค้าต่างหน่วยเข้าด้วยกัน

แนวทางที่เลือกคือ Quiet Gallery: ภาพขนาดกลางบนพื้น neutral พร้อมรหัสเด่นใต้ภาพและลูกศร ทั้งภาพและรหัสเป็นปุ่มเดียว ไม่มีปุ่มซ้อนหรือข้อมูลใหม่ใน schema ภาพช่วยตรวจยืนยันรหัสและรหัสช่วยตรวจยืนยันภาพ

- 320–600px: 2 คอลัมน์ รูปสี่เหลี่ยมจัตุรัส รหัสเต็มตัดบรรทัดได้
- ตั้งแต่ 601px: 3 คอลัมน์ ใน content width ไม่เกิน 1120px
- ไม่มีรูปใช้ placeholder ขนาดเท่ากัน ไม่ใส่รูปสมมติในข้อมูลร้านจริง
- รหัสยาวตัดบรรทัดได้ ไม่ใช้ ellipsis ปิดรหัสที่เจ้าของร้านต้องจำแนก
- Back คงคำค้นและคืน focus ไปที่การ์ดเดิม

อัปเดต DESIGN.md, UX-CONTRACT.md และ responsive tests พร้อม implementation; แบบ Compact Cards และ Split Workspace เป็นตัวเลือกที่ไม่ได้เลือก

## รายละเอียดสินค้า: ไซซ์มาก่อนสี

Desktop ใช้สองส่วน: รูปและรหัส/แก้สินค้าด้านซ้าย พื้นที่เลือกไซซ์และการ์ดสีด้านขวา Mobile ใช้รูปขนาดเล็กพร้อมรหัส จากนั้นไซซ์และการ์ดสีเรียงลงมา

เมื่อเพิ่งเปิดรายละเอียด ไซซ์ยังไม่ถูกเลือก แสดงคำแนะนำให้เลือกไซซ์ เมื่อเลือกแล้วจึงแสดงการ์ดแยกสีหรือแพ็กคละ

การ์ดแต่ละสีแสดงชื่อสี ราคา/หน่วย และ “ขายได้” เป็นจำนวนหลัก พร้อม “คงเหลือ” และ “จอง” เป็นจำนวนรอง ทุกจำนวนมีหน่วย ปุ่มเพิ่มสต็อก/ปรับจำนวนอยู่ในแต่ละการ์ดและใช้ editor/validation เดิม

ตัวอย่างข้อมูล: คงเหลือ 24 แพ็ก จอง 6 แพ็ก ขายได้ 18 แพ็ก เมื่อมี shortage ใช้ข้อความสถานะที่อธิบายปัญหาและคงกติกาเดิม การแก้ข้อมูลหรือเปลี่ยนไซซ์ขณะมี draft ผ่าน unsaved guard เดิม

## บิล: รายการและยอดที่อ่านออก

หน้าหลักใช้ heading/CTA grammar เดียวกับสินค้า แบ่งบิลตามวัน Asia/Bangkok และใช้ tab บิลเดิม เลือกแล้วจึงแสดงบิลกระดาษครั้งละหนึ่งฉบับ เก็บ keyboard Arrow/Home/End

ยอดขายของวันรวมเฉพาะบิล active ตามกติกาเดิม บิลยกเลิกยังเปิดหาได้ ไม่เปลี่ยนยอดนี้เป็นกำไรหรือยอดหลังคืนเงิน

หน้าสร้าง/แก้บิลจัดข้อมูลลูกค้าและรายการเป็นส่วนงานหลัก Desktop มี summary ข้างรายการ Mobile เรียง summary และปุ่มบันทึกก่อนตัวอย่างกระดาษบิล มีปุ่มบันทึกหลักเพียงชุดเดียวและเลื่อนพ้น dock ได้

บิลกระดาษและ PNG ใช้ receipt tokens เดิม ธีมเปลี่ยนเฉพาะ UI รอบกระดาษ Export ไม่ตัดสต็อก บันทึกบิลจึงตัดสต็อกตามคำสั่งเดิม

## จอง: รู้ว่ารอใครและกันอะไรไว้

การ์ดแสดงชื่อลูกค้าเป็นหัวเรื่อง สถานะเป็นข้อความพร้อมสี รายการแสดงรหัส/ไซซ์/สี/จำนวน/หน่วย ปุ่มสร้างบิลจากจองเป็น action หลักของรายการที่ยัง active ปุ่มยกเลิกใช้ danger และ confirmation เดิม

รายการที่ซื้อครบหรือยกเลิกแสดงผลอ่านอย่างเดียวตามสิทธิ์เดิม ไม่เพิ่มเวลาหมดอายุ การชำระเงิน หรือการส่งข้อความอัตโนมัติ

## คืน/เปลี่ยน: อ่านผลก่อนบันทึก

คงลำดับเลือกการดำเนินการ → อ้างบิล → ของรับเข้า → สภาพของคืน → ของออกกรณีเปลี่ยน → ผลต่อสต็อก → บันทึก ใช้ native select และ field order เดิม

รับเข้าและส่งออกใช้หัวข้อแยกกันในโหมดเปลี่ยนสินค้า สภาพของคืนยังใช้กับทุกรายการในคำสั่งเดียว แสดงผลก่อน/หลังและหน่วยตามข้อมูลที่มีอยู่จริง ไม่เพิ่มการคำนวณเงินคืนหรือส่วนต่าง

Desktop ใช้พื้นที่กว้างไม่เกิน 960px เพื่ออ่านผลรวมกับรายการได้ Mobile เรียงเป็นคอลัมน์เดียวและเว้นระยะกลุ่มชัดเจน

## ตั้งค่า: จัดกลุ่มตามงาน

ใช้แถว icon/ชื่อ/คำอธิบาย/ลูกศรบนพื้นขาว มีเส้นแบ่งเบา กลุ่มร้านของคุณ การใช้งาน ข้อมูลและประวัติเปิดหน้าย่อยตามระบบเดิม เนื้อหากว้างไม่เกิน 760px

บัญชีและความปลอดภัยแสดงเฉพาะโหมดที่มี account จริง โหมดออนไลน์ยังจำกัดการนำเข้าไฟล์ตามระบบปัจจุบัน ข้อความข้อมูลบนเครื่อง/บัญชีแยกตามโหมด ไม่อ้างว่าทุกโหมดซิงก์หรือกู้ข้อมูลได้เหมือนกัน

การกลับจากหน้าย่อยคืน focus ไปที่แถวเดิม draft ข้อมูลร้านไม่หายเพราะเปลี่ยนหน้าตั้งค่า และการออกจากฟอร์มยังใช้ guard เดิม

## ขอบเขตการตรวจเมื่อพัฒนา

แอปทำงานทั้ง local `/app` และ cloud `/shop` ตามเส้นทางปัจจุบัน ธีมนี้ครอบคลุมห้าพื้นที่ทำงานและหน้าย่อยของมัน Landing และ auth ไม่ถูกเปลี่ยนตามข้อเสนอนี้

แหล่งตรวจหลักคือ `npm.cmd run theme:check`, `npm.cmd run typecheck`, `npm.cmd run lint`, `npm.cmd test`, `npm.cmd run build` และ `npm.cmd run test:browser`

ต้องตรวจเว็บจริงที่ 320/390/768/1024/1440px, zoom 200%, ไทย/อังกฤษ, dock ที่แต่ละหน้าถูกเลือก, keyboard/focus, select เปิด, รหัสยาว, สถานะฟอร์ม, reduced motion, forced colors และการเลื่อนปุ่ม/ข้อผิดพลาดพ้น dock รวมถึงใบเสร็จที่ยังใช้ theme เดิม

ภาพ AI และผล build เพียงอย่างเดียวไม่ใช่หลักฐานว่า responsive, contrast, ขนาดแตะ หรือ flow ข้อมูลผ่านแล้ว
